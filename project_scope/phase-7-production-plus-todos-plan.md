## Guardrails

These hold for *every* commit below. A change that would violate one is wrong, not clever.

- **The user runs all code.** Extractors, migrations, `psql`, `dbt build`, `pytest`, deep-rescan dispatches, cassette re-recording, and git commits/merges are all operator actions. Commit rows describe the edits + the commands/SQL to run; they never assume the agent ran them. Every commit row tags whether it is a **[code/doc edit]** (agent-authored, user reviews + commits) or **[user-run]** (operator executes code against Neon/GHA/the network). `gh pr create` is OK on explicit request; the user runs the merge.
- **Never advance `source_watermarks` on a deep-rescan.** The incremental path owns the watermark exclusively. This is criterion (c) of the deep-rescan validation (WS-H) and a hard invariant of every cron/transform change.
- **Do not weaken the per-source dedup oracle** (`src/bronze/dedup_contracts.py`). Anything near `content_hash` / identity (notably TODO #72's `self._loader` question and any USDA staging change that touches dedup inputs) gets a concrete one-row trace *first*. The dedup-trap discipline: trace the edit scenario before adopting any "seems faster/cleaner" path.
- **Bronze stays storage-forced-only (ADR 0027).** The USDA native-array upgrade (WS-B) changes *silver consumption* of already-captured bronze jsonb; it does **not** re-normalize in bronze. `_to_str_list` / `_UsdaStrList` replay-safety stays intact (1-element arrays from migrated/replayed legacy rows are opaque, never re-split).
- **Quality gates per code/script change:** `ruff check`, `ruff format --check`, `pyright` (config covers `src/`, `scripts/`, `tests/`), and `pytest` green. dbt changes need a green `dbt build` (+ `dbt test`). Scripts are held to the same bar as `src/` and must be verified immediately, with `tests/scripts/test_<name>.py` coverage for any pure logic (parse/transform behind functions, network/DB behind a seam).
- **Version bump = manual edit to `pyproject.toml` only** (internal pkg; `recalls version` reads it via `importlib.metadata`). Proposed as the **final commit before go-live** (WS-H).
- **Single-home documentation rule.** Every fact has one owner; plans point, they do not restate. New tables/views/models get paired doc-update tasks (architecture / data_schemas / silver_design_notes / gold_design_notes). The doc sweep (WS-F) enforces this and flips merged plans to `Complete`/`Archived`.
- **ADR numbers come from `decisions/README.md`,** never reserved independently in a plan. Reference docs by section anchor / pointer, never line number.

## Risks & sequencing notes

- **The firm-sidecar rename (C19) is the hardest ordering constraint.** Its zero-cost window closes the instant the transform cron (C25) banks the first SCD-2 edit-version — after that the rename becomes a data migration, not a find-replace. C19 **must** merge before C25 runs against prod. The idempotency gate (snapshots re-bank 0 versions) is the proof it's still safe.
- **Pre-cron blockers gate go-live, not each other.** H-b (deep-rescan validation) gates both H-c (CPSC seed) and C40 (turn-on). H-a (simulation) precedes H-b. None of WS-A…G should wait on WS-H — they land first so the simulation exercises the *final* code.
- **`*_rejected` REVOKE (C31) needs a role decision before it means anything.** A single-role REVOKE would also block legit DDL. Provision the restricted app role first (ADR 0013 amendment), or the migration is a no-op guard. Sequence the ADR amendment ahead of the migration within C31. It also repoints `NEON_DATABASE_URL` for every cron/transform run, so wire the C25/C32 secret-validation to the two-role topology in the same pass — otherwise cron auth breaks at go-live.
- **Two doc-vs-reality gaps already ship as if fixed** — `operations.md` (secret-rotation workflow) and `re_baseline_playbook.md` (two PR gates). C27 + C28 make reality match the docs; until then the docs over-promise. Land both before go-live.
- **NHTSA `track_presence` (C16) data validity lags its code.** The code lands in WS-C, but the presence dims are only correct after the full-enumerating NHTSA run in H-b. Land the code; validate the data in WS-H; the registry pin (C39) prevents an accidental CPSC/FDA flip.
- **DQ severity escalation (C30) is gated on the framework decision (C29) and the Neon-branch fixture (C23).** Do not special-case one test's severity before the framework handles it systematically (inconsistent `source_assumptions` dir = future confusion). C30 is among the last to land.
- **Cassette re-record (C8) and the 2–3 day simulation (H-a) are the two biggest network/time costs** and are user-run. If the user defers the ~14MB cassette re-record, document the cassettes as intentionally pre-change-shape (array coverage already lives in the schema unit tests) rather than blocking.
- **Don't weaken the dedup oracle.** TODO #72 (`self._loader`) is validated as a near-no-op (stateless loader, rebuilt cheaply, carries per-source dedup-contract identity) — **resolve it by closing the TODO with a negative result, not by refactoring near `content_hash`.** If the user insists on the hoist, it goes on an opportunistic sibling branch with a one-row dedup trace, not here.
- **USCG `manufacturer_details` Tier-2 — shard param BUILT (Q6, 2026-06-09).** The full sweep is >6h (GHA cap), so it now runs a **strided 1/3 shard per month** via `recalls deep-rescan uscg_manufacturer_details --shard N --shard-count 3`, covering the full corpus per quarter (ADR 0010). It was **not onerous**: a pure `shard_work_list()` strided-slice helper + 2 loader fields + 2 CLI options + a unit test + the workflow cron — and **stateless** (the workflow derives the shard from the calendar month), which sidesteps the persistent per-shard cursor ADR 0010 feared. `deep-rescan-uscg-manufacturers-detail.yml` now has a guarded monthly cron (`30 6 1 * *`, `timeout-minutes: 330`). **WS-H must validate a real 1/3 shard completes under the timeout on GHA** before relying on the cron (raise `--shard-count` if it runs long).
